# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트 팀을 스스로 편성하고, 모집 마감 뒤 남은 학생은 AI가 배정안을 내면 앱이 규칙으로 검사해 관리자가 확정한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생 | 학번/비밀번호(1234)로 로그인, 팀 목록과 팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성/거부 |
| 관리자 | 학번 `admin`(비밀번호는 비밀 값 `ADMIN_PASSWORD`)으로 로그인, 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 기능 요구사항
1. **명단 올리기**: UTF-8(BOM 허용) CSV `student_no,name,main_role,sub_roles`와 팀 수를 넣으면 지원·투표·팀원·마감 표시를 지우고 학생과 빈 팀(팀1…팀N)을 만든다. 관리자 계정은 남긴다.
2. **지원**: 빈 팀이면 바로 승인, 팀원이 있으면 대기. 꽉 찬 팀, 주 역할이 같은 팀원이 있는 팀, 이미 팀이 있거나 대기 중인 지원이 있을 때, 마감 뒤, 필수 포함 역할 자리가 모자라게 되는 지원은 "막힘".
3. **투표**: 지원 팀의 그때 팀원 전원이 투표한다. 한 명이라도 거부하면 바로 거절, 전원 찬성이면 승인 직전 규칙을 다시 검사해 승인 또는 거절. 투표는 바꿀 수 없다.
4. **마감**: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠진다.
5. **배정**: 규칙을 지키는 배정이 있는지 먼저 확인(없으면 이유를 보이고 AI를 부르지 않음). 오픈라우터 1차→2차→3차 모델을 모델마다 120초 전체 대기 시간으로 부르고, 답을 검사 다섯 가지로 걸러 낸다. 3차까지 실패하면 앱이 모든 경우를 따져 배정한다. 검사를 통과한 배정안만 보여 주고, 관리자가 확정하면 DB에 저장한다.
6. **다른 사람의 변경 보기**: 화면이 3초마다 바뀐 부분만 다시 그린다(`st.fragment`).

## 4. 팀 규칙
- 확정한 팀은 2~4명(빈 팀 없음)
- 한 팀에 주 역할이 같은 학생 2명 이상 금지
- 모든 팀에 기획자와 웹 프로그래머를 서로 다른 학생이 1명씩 맡음(주 역할 또는 보조 역할)

## 5. 비기능 요구사항
- 비밀번호는 bcrypt 해시로 저장. 키·DB 주소·관리자 비밀번호는 `.env`/Streamlit Secrets에만 두고 화면에 출력하지 않음
- 테이블 이름은 `tf_`로 시작. DB 유일성 제약으로 한 자리에 한 명, 한 학생은 한 팀
- DB 연결은 연결 풀로 한 번 만들고 다시 씀
- 화면 요소 key는 공고 2.7절 표와 같음. 결과 안내는 "승인/대기/거절/막힘"으로 시작
- Streamlit Community Cloud에 배포, Supabase는 매일 질의로 일시정지 방지

## 6. 범위 밖
구글 로그인, 학생의 역할 수정, 투표 바꾸기
