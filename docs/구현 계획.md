# 구현 계획

## 1. 파일 구성
| 파일 | 내용 |
|---|---|
| `streamlit_app.py` | 화면(로그인, 학생 화면, 관리자 화면). key는 공고 2.7절과 같음 |
| `core.py` | DB 연결 풀, 규칙 검사, 지원/투표/마감/명단, AI 배정과 자체 배정 |
| `schema.sql` | `tf_` 테이블과 제약. 앱이 시작할 때 실행함 |
| `.github/workflows/keepalive.yml` | 매일 DB 질의(Supabase 일시정지 방지) |
| `practice/*.csv` | 연습용 시나리오 명단 |

## 2. 단계
1. **DB**: `schema.sql` 작성 → 앱 시작 시 실행 → 관리자 계정 만들기/비밀번호 갱신
2. **로그인**: 학번으로 찾고 `bcrypt.checkpw`로 비교, 세션에는 학번만 저장
3. **명단 올리기**: `utf-8-sig`로 읽고 열·역할 검사 → 한 트랜잭션에서 지우고 다시 만듦
4. **규칙 함수(순수 함수)**: `join_problem`(정원, 주 역할 중복, 필수 역할 자리), `team_problems`, `validate_assignment`(검사 5가지)
5. **지원/투표**: 팀 행을 `select … for update`로 잠가 같은 팀 처리를 한 번에 하나씩(=투표가 끝난 순서) 처리. 승인 직전 `join_problem` 재검사
6. **마감**: advisory lock(배타)으로 지원/투표와 섞이지 않게 처리
7. **배정**: `diagnose`(분명히 불가능한 이유) → `solve_assignment`(백트래킹, 빈 팀 대칭 제거) → AI 1~3차(모델마다 새 스레드 + 1초 단위로 전체 시간을 재서 120초에 끊음) → 실패 시 자체 배정 → 배정안을 `tf_settings`에 저장 → 확정 때 다시 검사 후 저장
8. **화면 갱신**: 학생 화면 전체와 관리자 화면의 팀 현황을 `@st.fragment(run_every=3)`로 감쌈
9. **시험**: 연습용 시나리오 3개를 단계마다 확인 → README 사례 기록
10. **배포**: 비공개 저장소 → Streamlit Cloud(Secrets) → 공개로 바꾸고 시크릿 창에서 확인

## 3. 고른 해결 방법
| 기능 | 해결 |
|---|---|
| 다른 사람의 변경 보기 | 어려운 해결: `st.fragment(run_every=3)` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결: 지원 단계에서 자리 계산으로 막음 (+ 배정 단계에서도 "규칙을 지키는 배정이 없음" 안내) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결: 승인 직전 재검사, 투표가 끝난 순서로 처리 |
| 마지막 자리에 두 명이 동시에 | 어려운 해결: `tf_members` 기본 키 `(team_id, slot_no)`, `student_id unique` |
| AI 응답이 늦을 때 | 어려운 해결: 모델마다 120초 전체 대기 시간 |
| 3차 모델까지 실패 | 어려운 해결: 모든 경우를 따지는 백트래킹 |
| AI 대기 중 화면 | 어려운 해결: "N차 모델(이름)의 응답을 기다리는 중… 초" |
| DB 일시정지 | 어려운 해결: GitHub Actions 예약 실행으로 매일 질의 |
